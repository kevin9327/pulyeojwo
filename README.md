# 풀어줘 — 공문·고지서 해독 AI 비서

어렵게 쓴 **공문·고지서·안내문·문자**를 붙여 넣으면(또는 사진·PDF를 올리면)
**쉬운 말로 풀고, 해야 할 일·기한·금액을 뽑아, 원문과 대조해 검증한 뒤, 캘린더(.ics)에 담아 주는** AI 에이전트입니다.

- **바로 써 보기(공개 실행 URL)**: https://kevin9327.github.io/pulyeojwo/ · 소스: https://github.com/kevin9327/pulyeojwo
- 설치 없음 · 서버 없음 · 의존 라이브러리 0개(순수 HTML/JS, Node 20+는 테스트에만 필요)
- AI 키가 **없어도** 날짜·금액·합계 검산·사기 의심 점검·어려운 말 풀이·캘린더가 동작합니다. **쉬운 말 풀이·놓친 기한 점검·답장 초안·사진·PDF 읽기는 AI가 필요**하고, 키가 없으면 챗봇에 복사·붙여넣기(아래 ②)로 같은 검증을 거쳐 쓸 수 있습니다.
- **10초 체험(키 불필요)**: 화면의 예시 문서를 하나 누르고 **‘▶ 키 없이 보기’** 를 누르면, 미리 받아 둔 **실제 Gemini 답**을 같은 검증기에 넣어 AI를 켠 화면을 보여 줍니다(지금 AI를 부르는 것이 아니라 기록 재생이라고 화면에 표시됩니다).

## 실행 방법

| 방법 | 순서 |
|---|---|
| ① 가장 쉬움 | `dist/pulyeojwo.html` 파일을 더블클릭(브라우저에서 열림). 한 파일로 묶어 둔 버전입니다. |
| ② 개발용 | `node serve.mjs` → http://localhost:8080 (`index.html` + `js/` 모듈) |
| ③ 직접 | 아무 정적 서버(`python -m http.server` 등)로 이 폴더를 열고 `index.html` 접속 (ES 모듈은 `file://`에서 막히므로 ①번 사용) |

화면 왼쪽의 **예시 문서**(모두 지어낸 가상 문서)를 누르면 바로 결과가 나옵니다. 주소 뒤에 `?sample=fine|insurance|rental|school|smishing|n2_parcel|n3_checkup|n4_telecom|n5_refund|n6_meal|n7_hospital` 를 붙여도 됩니다. 예시는 11개: 처음 5개는 개발 중에 만든 것이고, 뒤 6개(‘새’ 표시)는 **개발 뒤에 새로 쓴 문서**로 실제 Gemini 답을 받아 둔 것입니다(‘▶ 키 없이 보기’가 모두에 대해 동작).

### AI 켜기 (선택) — 키가 있을 때 / 없을 때
> **검증 현황(2026-10-29)** — 실서버(Gemini API 직접 호출) 기록과 한계를 숨기지 않고 적습니다.
>
> - **10/28**: 직접 호출 7건 중 6건 성공(글 5건 중 4건, 사진 1건, PDF 1건). 1건은 모든 후보 모델이 503(‘high demand’)이라 실패해, **503·429·시간 초과도 다음 후보 모델로 넘기도록** 고쳤습니다.
> - **10/29 새 문서 시험**: 앱을 만들 때 쓰지 않은 **새 가상 문서 8종**(`real_api/newdocs.mjs`: 연금 체납·택배 스미싱·건강검진·통신요금·환급 사칭 스미싱·급식비 환불·진료비·임대차 갱신 거절)을 실제 Gemini에 보냈고, **6종은 성공, 2종(연금 체납: 503 과부하, 임대차: 무료 일일 한도 소진)은 못 돌렸습니다.** 성공한 6건의 **첫 답에서 검증기가 건 ⚠ 는 1건뿐**이었고, 그것은 AI의 오류가 아니라 **우리 검증기의 오탐**(건강검진 안내의 ‘본인부담금 0원’을 금액으로 읽지 못함)이어서 **엔진을 고쳤습니다**(그래서 지금 이 6건은 모두 0건 통과이며, 이 6건은 *고친 뒤에는* 회귀 시험입니다). 사기 문자 2건은 AI가 모두 ‘높음’으로 판정했고(규칙 단독은 환급 사칭=높음, 택배=주의), 사기 점수는 올리기만 하므로 최종 ‘높음’이었습니다. 답은 `test/real/api2_*.json` 에 저장돼 있습니다(모델은 gemini-3.6-flash·3.5-flash — 기본 후보 3.8은 그날 무료 일일 한도가 소진돼 못 썼습니다).
> - **재수정 루프의 실서버 실행**: 실제 Gemini 답(과태료 안내)의 두 곳을 **사람이 일부러 틀리게 바꿔**(기한 → 문서에 없는 11/30, 금액 ×10) 검증기에 넣으면 2곳에 ⚠ 가 뜨고, 걸린 목록만 같은 모델에 다시 보내면 **실제 Gemini가 고쳐 보낸 답이 검증을 통과**했습니다(걸린 항목 2 → 0, `test/repair_demo_fine.json`, 같은 시험은 `test/run.mjs` 에도 있음). ‘주입한 오류’이지 모델이 자연스럽게 낸 환각이 아니라는 점을 분명히 합니다. 같은 문서의 실제 답 중에는 **모델이 기한 1건(부과 후 납부기한 12/11)을 빠뜨린 것**을 ‘놓친 기한’으로 짚어낸 사례도 있었고(주입 아님), 재요청에서 그 기한까지 채워 왔습니다.
> - **아직 안 한 것**: Claude·OpenAI 호출의 실서버 시험, 사진·PDF의 반복 시험(각 1건), 재수정이 *실제로 필요했던* 사례(자연 발생은 아직 못 봄 — 새 문서 6건은 모두 첫 답이 통과). 키 없이 쓰기(②)는 Gemini 웹 답 3건으로 확인했습니다.
**① API 키가 있으면** 아래처럼 직접 호출합니다. **② 키가 없으면** 같은 화면의 ‘키가 없으면? 챗봇에 복사·붙여넣기’를 쓰세요: `질문 복사`로 앱이 만든 질문(개인정보는 가린 상태)을 복사 → gemini.google.com 같은 챗봇에 붙여넣어 보냄 → 받은 답(JSON, 코드블록으로 감싸져도 됨)을 `답 넣기` 칸에 붙여넣으면 **같은 검증·자기 점검 흐름**이 돕니다(검증에 걸리면 ‘수정 요청 복사’로 같은 대화에서 한 번 더 고치게 할 수 있음). 시연 영상과 `test/real/` 시험값은 이 방식으로 **Gemini 웹에서 실제로 받은 답**입니다.

#### API 키로 직접 호출
`AI 켜기`를 펼쳐 제공자(Google Gemini / Anthropic Claude / OpenAI)와 **본인의 API 키**를 넣습니다.
키는 화면에서 고른 제공자의 주소로만 브라우저가 직접 보내며(서버 없음, 페이지의 CSP `connect-src` 도 이 3곳으로 제한), **제공자별로 따로** 보관하므로 드롭다운을 바꿔도 다른 회사로 가지 않습니다. 코드나 이 저장소에는 키가 들어 있지 않고, `이 브라우저에 키를 저장`을 체크하지 않으면 새로고침 때 사라집니다.
AI에 보내기 전 **주민·외국인등록번호, 운전면허번호, 여권번호, 카드번호, 사업자번호, 계좌, 전화, 이메일은 자동으로 가려서** 보냅니다(끌 수 있음). **이름·주소**는 규칙으로 가릴 수 없어 화면의 **‘더 가릴 말’ 칸**에 적은 낱말만 가립니다(적지 않으면 그대로 전송). 차량번호 등 그 밖의 정보도 같은 칸에 적으세요. 사진·PDF는 가릴 수 없으니 필요한 부분만 올리세요.

## 에이전트가 하는 일 (한 번의 ‘풀어줘’)

```
① 읽기  → ② 날짜·금액 뽑기(이 기기, AI 없이) → ③ 쉬운 말로 풀기(AI) → ④ 원문과 맞춰 보기(검증)
        └ 걸린 게 있으면 ④′ AI에게 ‘걸린 부분만’ 다시 고치게 하고 재검증(1회, 나아졌을 때만 채택)  → ⑤ 챙기기(캘린더·할 일·답장 초안)
```

| 기능 | AI 필요 | 설명 |
|---|:-:|---|
| 날짜·시각·요일 | 아니오 | `2026. 11. 13.(금)까지`, `11월 10일(화)`, `오후 6시` 등 읽기. 기한/기준일/행사 구분, 연도 없는 날짜는 문서 기준일로 추정, **요일이 날짜와 안 맞으면 경고** |
| 금액·계좌·합계 검산 | 아니오 | `2,150만 원`, `12만 3,000원` 같은 한글 단위 해석, `합계 ○○원`이 앞 금액을 더한 값과 맞는지 검산 |
| 사기 의심 점검 | 아니오 | 단축 URL·기관 사칭 주소(.go.kr 아님)·인증번호/앱 설치/안전계좌 요구·재촉·요일 불일치 등. 110·118·112 안내 |
| 어려운 말 풀이 | 아니오 | 행정·세무·계약 용어 100여 개 사전. 원문에서 눌러 보면 뜻이 나옴 |
| 캘린더(.ics) | 아니오 | 기한마다 7일 전·1일 전 알림이 붙은 일정 파일 (RFC 5545, 줄 접기·이스케이프 처리) |
| 쉬운 말 풀이·할 일·놓치면 생기는 일·답장 초안 | 예 | LLM이 JSON으로 답하고, 모든 항목에 **원문 인용(evidence)** 을 달게 함 |
| 사진·PDF 읽기 | 예 | 사진은 Gemini·Claude·OpenAI, PDF는 Gemini·Claude(OpenAI는 PDF 미지원 — 명확한 오류로 안내). AI가 읽은 글자를 ‘원문’으로 삼아 같은 검증을 적용하므로 **독립적인 원문이 아니라 AI가 읽은 글자 기준**입니다(화면에도 표시) |

### AI를 믿지 않는 설계
1. **원문 대조 검증기** — (검증하는 것: 할 일·금액·불이익 항목의 날짜·금액·인용문, 그리고 한 줄 요약·쉬운 풀이·답장 초안·할 일 문구·금액 이름에 들어간 날짜·금액. 검증하지 않는 것: 문장의 의미(조건·적용 범위), 용어 풀이, 기관에 물을 질문 문구.) AI가 말한 날짜·금액이 원문에서 이 기기가 직접 뽑은 값과 일치하는지, 인용문이 원문에 있는지, **인용문 속 날짜·금액이 주장한 값과 같은지**(다른 문장을 끌어다 붙인 경우)를 확인합니다. 어긋난 항목은 `원문에 없음` 으로 표시하고 **캘린더에 넣지 않습니다.**
2. **AI가 빠뜨린 기한** — 엔진이 찾은 기한 중 AI 답에 없는 것을 따로 알려 줍니다.
3. **사기 점수는 올리기만** — AI가 “안전”이라 해도 규칙 점검이 높으면 높게 유지합니다(글을 직접 넣은 경우. 사진·PDF 는 규칙이 AI가 옮겨 적은 글자에서 돌아, AI가 사기 문구를 지우고 옮기면 하한이 약해집니다). 문서 안의 “이전 지시를 무시하라”·“안전하다고 답하라” 같은 문장은 **규칙이 숨은 지시문(프롬프트 주입 시도)으로 탐지해 사기 점수를 올리고**, 규칙 결과를 바꾸지 못합니다(테스트 포함).
4. **자기 점검 루프(에이전트)** — 검증에서 걸린 항목만 AI에게 알려 한 번 고치게 하고, 다시 검증해 **나아졌을 때만** 받아들입니다(고치기 호출이 실패하거나 더 나빠지면 원래 답 유지). 여기서 ‘에이전트’는 *읽기→풀이→검증→재요청* 을 스스로 돌리는 폐루프를 뜻하며, 외부 도구를 고르는 계획형 에이전트는 아닙니다.
5. **사기 문서는 ‘하지 마세요’** — 사기 의심이 높으면 문서의 요구를 할 일·캘린더로 만들지 않고 ‘따르지 마세요’로 보여 줍니다.
6. **AI 실패 시 폴백** — 호출이 실패해도 이 기기 분석 결과는 그대로 보여 줍니다. 기본 Gemini 모델 이름이 바뀌어 404가 나면 후보 모델로 한 번씩 더 시도합니다.

## 테스트
```
node test/run.mjs      # 69개: 날짜·금액·합계·사기 점검·ICS·검증기(인용 대조)·에이전트 루프·마스킹·JSON 읽기·성능·AI 호출 형식(가짜 fetch)
node test/corpus.mjs   # 20건 시험 모음: 기한·금액·사기 점검 기대값과 비교 (-v 로 건별 결과)
```
**시험 모음의 성격(숨기지 않고 적습니다)**: 20건은 예시 5개와 별도로 제가 새로 쓴 글이고, 기대값은 엔진 출력을 보기 전에 글을 읽고 적었습니다. 처음 돌렸을 때는 **14/20** 이었고, 틀린 6건(‘납기일:’·‘결제일’ 뒤 날짜를 기한으로 못 읽음, 시각이 붙은 일정 구분, ‘11. 20.(금)’ 형태의 범위 끝 날짜, ‘30만원어치’ 금액)을 고쳐 20/20 이 됐습니다. 그래서 **이 20건은 지금은 회귀 시험이지 독립 시험이 아닙니다.** 실제 공문 수백 건으로 잰 정확도가 아니며, 새 글에서 틀릴 수 있다는 전제로 화면의 ‘원문에서 표시한 곳’ 카드로 어느 글자에서 읽었는지 함께 보여 줍니다.
AI 호출 테스트는 네트워크 대신 가짜 `fetch`로 요청 형식(헤더 키, JSON 모드, 이미지 첨부)과 응답 해석, 오류 처리를 확인합니다. **API 서버 호출은 사용자 키가 필요해 자동 테스트에는 없습니다.** 대신 `test/real/` 의 **실제 Gemini 답 13개**(웹 3개 + 10/28 API 4개 + 10/29 새 문서 API 6개, 원문 그대로)를 검증기에 통과시켜 실제 모델 출력 형식·인용 품질이 검증기와 맞는지 확인합니다. 새 문서 6개(`api2_*`)는 앱을 만든 뒤에 만든 문서라 독립 시험에 가깝지만, 첫 시험에서 나온 오탐(0원)을 고친 뒤의 값이라 지금은 회귀 시험이기도 합니다. 시연 영상은 웹 답과 오류 주입 기록을 사용합니다.

## 한계
3만 자를 넘는 글은 앞 3만 자만 분석하며 화면에 경고를 띄웁니다. 요약·풀이·답장 속 날짜·금액은 원문에 있는 값만 허용하는 보수적인 검사라, ‘오늘 중·내일까지·모레까지’ 같은 상대 기한은 기준일로 환산해 인정하지만, 그 밖의 말바꿈(‘다음 주 금요일’ 등)은 ⚠로 표시될 수 있습니다. 시험 모음 20건은 첫 실행에서 틀린 것을 고친 뒤의 회귀 시험이며 독립 시험이 아닙니다.
법률·세무 자문이 아닙니다. 날짜·금액은 보낸 기관에 한 번 더 확인하세요. 규칙 기반 사기 점검은 알려진 유형 위주라 새 수법은 놓칠 수 있고, 사진 속 글자 읽기는 AI 품질에 의존합니다. ‘송달받은 날부터 2주 이내’ 같은 상대 기한은 받은 날을 알 수 없어 날짜로 계산하지 않고, ‘상대 기한도 있어요’ 로 문장 그대로 알려 줍니다(일·주·개월 단위). 공식 도메인 목록은 대표 기관·서비스 일부만 담고 있어, 목록에 없는 정상 주소가 ‘공식 주소 아님’으로 표시될 수 있습니다(이때도 점수만 올릴 뿐 차단하지 않습니다).
